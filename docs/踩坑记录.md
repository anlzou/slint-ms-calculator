# Slint 1.18 + Rust 踩坑记录

> 本项目（Slint 1.18.1 + Rust，Windows 11）开发过程中实际踩过、验证过的坑，按主题归类。
> 每条都给出症状与解法，供后续 Slint 项目参考。

## 1. 语言 / 语法层

| 症状 | 原因与解法 |
|---|---|
| callback 声明处写成 `callback x := { ... }` 报错 | callback 赋值用普通 `=`，不是 `:=` |
| 连字符属性名（如 `history-open`）在赋值语句里解析失败 | 作为**赋值目标**时不能用连字符名，内部状态改用无连字符名（如 `drawer`） |
| `if cond: { ... } else { ... }` 解析失败 | 条件元素**没有 `else:`**，写两个块：`if cond:` / `if !cond:` |
| `index % 4` 报错 | Slint 表达式里 `%` 不是取模运算符，用 `Math.mod(index, 4)` |
| `padding: 10px 16px;` 解析失败 | 没有 CSS 简写，`padding-left/right/top/bottom` 分开写 |
| "Unknown property vertical-alignment in Rectangle" | `Rectangle` 没有 `vertical-alignment`（只有布局和 Text 有） |
| 从 Rust 调 `ui.global::<Theme>()` 编译失败（E0425） | 入口 .slint 必须**再导出** global：`export { Theme } from "theme.slint";`，否则不生成对应 Rust 类型 |
| `private function foo(...)` 直接 Parse error（1.18） | 组件内**不支持 private 函数**（连字符函数名同样解析失败）；派生文本改用拼接属性：`property <string> hs: hyp ? "h" : "";` + `"sin" + hs + inv` |

## 2. 布局

| 症状 | 原因与解法 |
|---|---|
| 想要弹性占位找不到 `Spacer` | Slint 无内置 Spacer，用 `Rectangle { horizontal-stretch: 1 }` |
| 想用 `ListView` / `ScrollView` | 它们**不是内置元素**，用 `Flickable` + `content-height`（`viewport-height` 已废弃） |
| 布局写 `implicit-height` 报错 | 布局元素没有 `implicit-height` |
| 布局元素写 `bottom: 0` 解析失败 | 布局不接受 `bottom:` 定位属性；要让悬浮按钮不挡住最后一行，给外层 VerticalLayout 加 `padding-bottom` |
| **`if` 条件元素放在布局里，条件变 false 后格子仍占空间**（本项目：图钉按钮退出置顶后没有滑回原位、内容被裁切） | 改为**始终实例化 + 宽度折叠**：`visible: !cond` 且 `min-width/max-width: cond ? 0px : Npx`（高度同理），布局 `spacing` 也要跟着条件化 |
| **HorizontalLayout 把剩余空间分给没有 max-width 的格子**（"min-width: 26px" 的按钮实际渲染很宽，即使旁边有 stretch 项） | 固定尺寸按钮必须两侧都锁：`min-width: Npx; max-width: Npx` |
| 悬浮控件被抽屉遮罩盖不住 / 点击被抢 | **声明顺序即 z-order**：绝对定位的窗口级控件要声明在遮罩**之前**；覆盖层（overlay）永远声明在最后 |
| **放进布局里的 TouchArea 永远点不到** | TouchArea 在布局中隐式尺寸为 0；任何点击/hover 区域必须绝对定位并显式给 x/y/width/height |
| 想要单侧 1px 分隔线 | `Rectangle` 没有单边 border，沿边画一条 1px Rectangle（本项目：历史面板顶部分隔线、抽屉右边缘） |
| **`if` 条件元素上起的 id，组件树外部引用不到**（"Cannot access id 'skb'"，如主窗口想读条件键盘内部的浮层状态） | 把状态**提升到根组件属性**，实例处用**双向绑定**接回去：`menu-open <=> root.sci-menu;`（`in-out property` 允许外部双向绑定覆盖内部默认值） |
| 组件内部浮层的"点外部收起"遮罩盖不到组件外区域（点显示屏不收起） | 遮罩只能覆盖组件自身范围；组件外的大块区域（如 DisplayArea）在**父组件**里叠一个条件 `TouchArea`（`if 浮层打开: TouchArea { clicked => 复位状态 }`）补齐 |
| 四角圆角不一致（如抽屉面板左侧直角、右侧圆角） | Rectangle 的分角属性是 **CSS 风格** `border-top-left-radius` / `border-top-right-radius` / `border-bottom-left-radius` / `border-bottom-right-radius`；写成 `top-left-border-radius` 或 `top-left-corner-radius` 都会报 "Unknown property"（1.18.1 源码 `builtin_elements.rs` 可查证） |
| GridLayout 写 `columns: 6;` 报 "Unknown property columns in GridLayout" | Slint 的 GridLayout **没有** `columns` 属性，列数由子元素的最大 `col` 值自动推断；给每个子元素显式 `row: i / 6; col: Math.mod(i, 6)` 即可（科学键盘 6 列网格实测） |

## 3. 窗口 / 置顶（无边框）模式

| 症状 | 原因与解法 |
|---|---|
| Rust 侧找不到 `set_decorations` / `set_always_on_top` | `slint::Window` 没有这些方法；但 .slint 的 `Window` 有 `no-frame`、`always-on-top`、`resize-border-width`（winit 后端）属性，直接绑 bool 即可 |
| 无边框后窗口拖不动 | 顶栏空白区放 `WindowMoveArea { enabled: root.pinned; }`；普通点击不移动，子 TouchArea 照常响应 |
| 无边框后不能缩放 | `resize-border-width: root.pinned ? 8px : 0px`（winit 特性） |
| **动态切换 `no-frame` 后布局/渲染不刷新**：进入置顶显示不全、退出置顶关闭按钮不消失，手动拖一下边框才恢复（说明缺的是一个真实 resize 事件） | 在切换回调里用物理尺寸做**两步微扰**：`Timer::single_shot(120ms)` 里 `set_size(w+2, h+2)`，**再隔一拍**另一个 `single_shot` 里还原 `-2`。注意：同一个回调里先加后减**无效**——两次 set_size 会被合并成 0 变化，WM_SIZE 根本不发 |
| 用"隐藏旧窗口 + 重建新窗口"绕开上面的问题 | ❌ 用户可感知到关闭再弹出的动画，被否决；单窗口 + 微扰才是正解 |
| 无边框模式丢了 Win11 圆角 | 装饰切换会重建窗口样式，需重新施加 DWM 属性：`DwmSetWindowAttribute(hwnd, 33 /*DWMWA_WINDOW_CORNER_PREFERENCE*/, &2 /*DWMWCP_ROUND*/, 4)`；不引 crate，用 `#[link(name = "dwmapi")]` + `FindWindowW` 按标题拿句柄即可 |
| 首显前 `set_size`/`set_position` 恢复几何不可靠（出现过 976x1071 的怪尺寸、位置偏移） | 几何恢复要在 `show()` 之后做，或干脆避免重建窗口路线 |
| 模式切换改绑 `preferred-height`（标准 580 → 科学 660），窗口尺寸纹丝不动、键盘底部两行被裁 | `preferred-width/height` **只在窗口创建时生效**，运行中改绑定不会 resize 已有窗口。解法：Rust 端跟踪状态变化，手动 `window().set_size(PhysicalSize::new((380.0*scale) as u32, (660.0*scale) as u32))`，scale 用 `window().scale_factor()`（1.18 没有 `set_size_logical`） |
| 普通（带标题栏）模式下底部两角是直角，置顶模式却已经圆了 | 顶部两角归窗口管理器管，底部两角没人管。Slint 的 `Rectangle` **只有统一的 `border-radius`，没有逐角半径**（`items.rs` 里 `border_radius: Property<LogicalLength>` 是一个标量），于是把 `corner-bg` 上移一个半径（`y: -radius`、`height: root.height + radius`），顶部那段圆弧整段落在窗外被裁掉，露出来的只有底部两角。实测顶部 6 行首个不透明像素 x 全 0、底部 6 行 12,7,6,4,3,3 |
| Linux 无边框模式没有圆角，四角是直角 | 没有 DWM 那种 API，合成器也不给无边框窗口加圆角 → 只能自绘：`Window { background: pinned && radius>0 ? transparent : Theme.window }` + 最底层一块 `Rectangle { background: Theme.window; border-radius: 12px }`。半径用 `in-out property <float>` 由 Rust 按平台置位（Windows 留 0 交给 DWM），别在 .slint 里写平台分支 |
| 以为"Slint 要不到透明窗口"（`Window` 没有 transparent 属性，`set_transparent` 的调用又被 `#[cfg(target_os = "macos")]` 圈住） | 其实 `WinitWindowAdapter::window_attributes()` 默认就是 `WindowAttributes::default().with_transparent(true)`，X11 上 winit 据此挑 32bpp ARGB visual，femtovg/wgpu 按 `attributes.transparent` 配表面——Linux 走的是"建窗即透明"，不需要运行时开关。**验证方式**：`XGetImage` 读回来的 32bpp 缓冲里第 4 字节就是 alpha，置顶时四角实测 alpha=0、中心 255，GL 与 `SLINT_BACKEND=software` 都一样 |
| 自绘圆角后右下角 `=` 键被切掉一角 | 圆弧是窗口遮罩，本来就会裁内容（Windows 的 DWM 圆角同理）。顶栏/关闭键都在 4px 内边距 + 12px 半径以内不受影响；要保内容完整只能加大内边距，代价是整体布局变化，未采纳 |
| 透明窗口在无合成器的裸 X11 上四角露黑 | 没有合成器就没有 per-pixel alpha 可用。属于环境限制，不在应用侧兜底（探测合成器存在与否要引 Xext，收益不划算） |

## 4. Rust 端 API

| 症状 | 原因与解法 |
|---|---|
| 想监听属性变化，写 `on_xxx_changed` 编译失败 | Slint **不会**为 property 生成 changed 回调；需要感知变化时显式声明 `callback`（本项目 `pin-toggled()`），UI 改属性后手动触发 |
| `s.width + 1.0` 类型错误 | `Window::size()` 返回整数 `PhysicalSize`（字段 u32）；**没有** `Window::logical_size()`；`slint::LogicalSize` 在 1.18 不带泛型参数（固定 f32）。逻辑尺寸自己算：`物理 / scale_factor()` |
| `slint::LogicalSize<f32>` 报泛型错误 | 同上，1.18 这些类型是非泛型的 |
| 找不到 `platform::StandardButton` / OpenLink | 1.18 未导出；打开 URL 用 `std::process::Command::new("cmd").args(["/C","start","",url])`；退出用 `slint::quit_event_loop()`（组件没有 `ui.quit()`） |
| 点关闭后窗口消失但进程不退出 | 处理 close 请求时先 `window().hide()` 再 `quit_event_loop()`，保证窗口即时消失且事件循环正常结束 |
| `slint::LogicalLength` 导入失败 | 1.18 不导出；跨边界传 `property <float>`，在 .slint 里 `* 1px`；生成的 float setter 收 `f32` |
| 键盘按键判断不生效 | `Window` 级 `forward-focus: kb;` 可用；`key-pressed` 处理完必须 `return accept;`；事件文本里 Enter 是 `"\n"`、Esc 是 `"\u{1b}"`、Backspace 是 `"\u{8}"` |
| 想跟随系统深色模式 | 1.18 没有 `Window::dark_color_scheme()`；Windows 下读注册表 `HKCU\...\Personalize\AppsUseLightTheme`（`reg query`） |

## 5. 图标 / 字体

| 症状 | 原因与解法 |
|---|---|
| Path 画的小图标（关闭 ×）在 36x28 按钮里定位漂移、画到格子外 | 简单字符改用 `Text { text: "×"; horizontal-alignment: center; vertical-alignment: center; }`——Text 铺满父 Rectangle，天然居中 |
| `⌫`（U+232B）在默认字体下渲染为空白 | 避免生僻 Unicode 图标，退格键用 `←` 代替 |
| `☰`(U+2630)、`≣`(U+2263) 渲染为空白，但按钮点击区域正常 | 这两个码位不在 Slint 默认字体回退链里；CJK 字符「三」用系统自带中文字体必能渲染，视觉上也是三条横线 |
| `▾`(U+25BE)、`▴`(U+25B4) 折叠箭头不显示 | 同类回退链缺字形问题；改用 emoji 箭头 `🔽`/`🔼`、`⬅️`（emoji 都有彩色回退）。**2026-10 再改**：emoji 在软件渲染器下又会空白，现已统一换成 `ui/icons/` 的单色 SVG（见下面两行） |
| `∛`(U+221B) 渲染为方框 □ | 同样缺字形；立方根标签拆成有字形的组合 `³√x`（³ 与 √ 都能渲染） |
| `⌊x⌋/⌈x⌉`(U+230A/2308 取整括号) 渲染为方框 | 同类缺字形；Slint 里无 MDL2 字体兜底，按钮文本退回 ASCII 词 `floor`/`ceil` |
| emoji 图标无法用 color 区分选中态 | Slint 的 Text color 对彩色 emoji 无效；选中/hover/按下状态改用**方块底色**（`Theme.key-hover` / `Theme.key-pressed` 三态）。换成单色 SVG 后 `Image { colorize: }` 生效，图标本身即可染色（置顶态图钉用 `Theme.accent`、无边框关闭键 hover 转白），底色三态保留 |
| 标题栏图标想要彩色 emoji | `Window` 的 `icon: @image-url(...)` 只吃图片；PowerShell GDI+ `DrawString` 渲染彩色 emoji 只会得到单色底层轮廓。当时的方案：图像生成彩色 PNG → 裁剪去水印 → 缩到 64x64 存 `ui/icon.png`。**2026-10 再改**：那张算盘位图已挪到 `ui/icons/icon-abacus.png` 留档，窗口图标换成自绘的 `ui/icons/app-calculator.svg`（矢量，resvg 光栅化后任意 DPI 都锐利，16px 下仍可辨认；实测 `_NET_WM_ICON` 单张 64×64、非透明 71.6%） |
| Segoe MDL2 Assets 私有区图标（`\u{e713}` 等） | 能渲染但仅限 Windows；本项目已全部替换为 emoji/Unicode（⚙️  ← ▾ ），保持跨平台可读性 |
| Linux 上 `SLINT_BACKEND=software` 时彩色 emoji 图标整块空白（🧮🧪📅💱🏃🕐），只有单色字体里查得到的（📈📦📏🌡）画得出来 | 软件渲染器没有彩色 emoji 字体（Noto Color Emoji 的 CBDT/COLR 分层）可回退；GL 路径（femtovg）正常。**根治**：图标不再依赖字体，全部换成 `ui/icons/` 下单色 SVG + `Image { colorize }`，两种渲染器实测都可见 |
| 想把图标做成可配置字符串（`glyph: "🧮"` 这种） | `@image-url()` 必须是编译期字面量，不能拼路径。做法：组件属性声明成 `in property <image> icon;`，在 `.slint` 构造点写 `icon: @image-url("icons/calculator.svg")`；二选一的图标可以直接 `source: cond ? @image-url(a) : @image-url(b)` |
| SVG 图标被拉变形 | `Image` 的 `image-fit` 默认 `fill`（横纵各自缩放到盒尺寸），非正方盒必然变形。图标盒一律取正方形（本项目 11~16px），要留白就在外面套定宽 `Rectangle` |

## 6. 构建 / 环境

| 症状 | 原因与解法 |
|---|---|
| `cargo build` 报 os error 5（文件被占用） | GUI 程序还在运行会锁住 exe，先 `taskkill //IM xxx.exe //F` |
| 改了 .slint 后 build.rs 像在用旧的生成代码 | `cargo clean -p <pkg>` 再构建 |
| `for` 循环 Repeater 放 GridLayout 里位置乱 | 子元素要显式给 `row: Math.floor(index / 4); col: Math.mod(index, 4);` |
| 脚本化 UI 验证时 CopyFromScreen 截到钉钉/浏览器等前台窗口 | 第三方 App 会抢回焦点；改用 `PrintWindow(hwnd, hdc, 2)`（PW_RENDERFULLCONTENT）按句柄抓取，不受 z-order 影响。PowerShell 里 `Add-Type -MemberDefinition` 必须带 `-ReferencedAssemblies System.Drawing`，否则 Bitmap.GetHdc 找不到；另外别在目标窗口上重复点击，winit 窗口在 resize/模式切换后句柄可能变化，点击前先重新枚举 |

## 7. Linux 下的脚本化验证（抓图 / 点击）

| 症状 | 原因与解法 |
|---|---|
| 抓整屏拿不到内容 | GNOME 50 的 `org.gnome.Shell.Screenshot` D-Bus 对普通进程返回 `Screenshot is not allowed`，抓 root 只有 344 个非黑像素，本机也没有 grim/spectacle。可行路线：`WAYLAND_DISPLAY` 置空让 winit 走 X11，再按 `_NET_WM_PID` 认领窗口、`XGetImage(0,0,w,h,ZPixmap,0xFFFFFFFF)` 抓客户区，PIL 以 raw `"BGRX"`（带 alpha 时用 `"BGRA"`）解 |
| 想注入鼠标键盘事件驱动界面 | ❌ 本机 XWayland 下不可行：窗口折算到 X root 是**负坐标**（实测 `(-870,-385)`），`XWarpPointer` 和 XTest 的 `MotionNotify` 都被夹到 root 边界 `(0,0)`，点击落不到窗口上；`XSendEvent` 造的事件又被 winit 按 `send_event` 标志丢掉。别在这条路上继续耗时间 |
| 上行的正解 | 走 Slint 自带的 system-testing 通道：`slint = { features = ["system-testing"] }` + `SLINT_EMIT_DEBUG_INFO=1` 构建，运行时 `SLINT_TEST_SERVER=127.0.0.1:<port>`。**是 app 反向连到测试脚本监听的 TCP**，帧 = 4 字节大端长度 + protobuf（`slint_systest.proto`）。`RequestFindElementsById` → `RequestElementClick` 就能派发真实点击，配合 XGetImage 断言结果 |
| `find_elements_by_id` 查不到 `menu-ta` | id 带组件前缀，要写 `MainWindow::menu-ta`；另外构建时没给 `SLINT_EMIT_DEBUG_INFO` 会直接回 `ErrorResponse`（"需要 debug info"），别误判成"元素不存在" |
| 抽屉开着时点 `pin-ta` 没反应，圆角断言全绿但其实没进置顶 | 按句柄点击**仍走命中测试**，上层遮罩会吞掉。测试序列要先关遮罩；这类"假绿"要主动构造反例（本项目改成单独一轮：不碰抽屉直接点 pin） |
| 同一套"开抽屉 → 点 `MenuItem#1` → 点科学键盘元素"的脚本，上一轮能查到 `ScientificKeypad::angle-ta`，下一轮报"找不到 id"，抓图却是标准键盘 | 不是 id 问题，是**模式没切过去**：点完菜单项没等窗口从 580 重排到 620，科学键盘还没实例化。跨模式序列每步都要 `wait`（实测开抽屉 700ms、切模式 1200ms 稳定），并且用窗口尺寸当断言（380×580=标准，380×620=科学）确认这一步真的生效，再往下点 |
